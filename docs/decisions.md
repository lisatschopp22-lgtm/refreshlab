# Decisions

One line per decision: date · decision · why. Started 2026-09-19.

- 2026-09-19 · Colour is a runtime palette, not a constant · The brand hue is undecided, so components use semantic tokens only and `npm run check` fails on raw colours. Four palettes ship; green is one of them, not the default in code.
- 2026-09-19 · Locale routing without middleware · Next 16 renamed `middleware.ts` to `proxy.ts`. next-intl works with a `[locale]` segment and `setRequestLocale`, so the prototype avoids that moving API entirely; `/` redirects to `/de`.
- 2026-09-19 · Email confirmation off for local sign-up · Registration would otherwise need a Mailpit round trip in every e2e run. Magic link and password reset still exercise real mail.
- 2026-09-19 · Drizzle columns are qualified by hand inside `sql` templates · Drizzle renders `${table.column}` unqualified, which is ambiguous in a correlated subquery that joins other tables. See the `qualified()` helper in `src/db/queries/catalogue.ts`.
- 2026-09-19 · Placeholder images are generated SVGs in real storage · The prototype has no photographs, but grey boxes make cards and galleries impossible to judge. The seed uploads 201 generated technical illustrations to Supabase Storage, so the storage path is genuinely exercised.
- 2026-09-19 · `search_text` is a trigger-maintained column, `search_vector` is generated from it · Lets the listing trigger cover edits while the outbox reindex covers catalogue renames, which a row trigger cannot see.
- 2026-09-19 · Search state lives in the URL, in German param names · Results stay shareable and server-rendered, and the param names match the visible routes (`zustand`, `hersteller`, `kategorie`). English aliases are accepted too.
- 2026-09-19 · Filtered search pages are `noindex, follow` · They are thin and near-duplicate. Category, manufacturer, model and listing pages carry the indexable content.
- 2026-09-19 · robots.txt names AI crawlers explicitly · Which crawlers may read public catalogue data is a commercial decision; a bare wildcard hides it. GPTBot, ClaudeBot, PerplexityBot and Google-Extended are listed so the choice is visible and revocable.
- 2026-09-20 · `proxy.ts` refreshes the Supabase session, nothing else · Next 16 renamed middleware to proxy. Without a refresh the prototype session expires after an hour mid-test. Locale routing deliberately stays out of it.
- 2026-09-20 · The required marker sits outside the `<label>` element · Inside it, the label's text becomes "Preis*", which breaks both screen-reader announcement and `getByLabel`. The input's own `required` carries the semantics.
- 2026-09-20 · A proposed model gets a `pending` catalogue record immediately · The seller must not be blocked while the catalogue is reviewed, so the listing can be published while the model record waits for approval. Its record number is suffixed `-P`.
- 2026-09-20 · Personal profiles are `noindex` · They carry a real person's name. Organisation pages are indexable, because they are businesses.
- 2026-09-20 · Comments nest one level only · A reply to a reply attaches to its root. Deep threads make a technical Q&A hard to scan, and the mockups show a flat question-and-answer shape.
- 2026-09-20 · Messages poll every five seconds instead of using Realtime · Enough to judge the behaviour, and it keeps the prototype free of a live subscription to reason about. Supabase Realtime remains a Phase 7 option.
- 2026-09-20 · A form must not unmount while its action is in flight · `useActionState`'s dispatch returns void, so awaiting it and then closing the form silently cancelled replies. Forms now close on the action's `ok` result.
- 2026-09-20 · Mailpit's SMTP port has to be published explicitly · `supabase/config.toml` ships it commented out, so only the web interface was reachable and every notification failed with ECONNREFUSED.
- 2026-09-20 · Controls that do different things get different labels · A reply toggle and a reply submit both reading "Antworten" is ambiguous for anyone navigating by button name.
- 2026-09-20 · Confirming receipt releases the payout · Stripe explicitly does not provide escrow, so holding the money until the buyer confirms is a marketplace rule enforced in `src/domain/orders.ts`, not a banking guarantee. `buyerConfirmsReceipt` remains a flag.
- 2026-09-20 · Who may make each transition is part of the state machine · A seller cannot confirm receipt for the buyer, a buyer cannot mark an item shipped, and only an admin resolves a dispute. Keeping this in the domain, not the UI, is what the unit tests check.
- 2026-09-20 · An accepted offer reserves the listing, completion sells it · A cancelled or refunded order puts it back on the market. The listing status follows the transaction rather than being set by hand.
- 2026-09-20 · The e2e suite reseeds before it runs · The journeys buy and sell real rows, so they are not idempotent. Without a reset, a second run finds its fixtures already sold. `E2E_SKIP_SEED=1` opts out while iterating.
- 2026-09-20 · Storage is cleared through the Storage API · Supabase now rejects `delete from storage.objects`, so the seed lists and removes the folders it owns instead.
- 2026-09-20 · An administrator cannot suspend themselves or drop their own admin rights · Either one locks the last administrator out of the console. The guard is in `src/domain/admin.ts`, not in the template.
- 2026-09-20 · Merging a model moves its listings and leaves a pointer · The duplicate keeps `merged_into_id` so old links still resolve, and every moved listing is re-indexed.
- 2026-09-20 · Every admin query is covered by an integration test · Correlated subqueries written by hand fail only at runtime, and the ambiguous-column bug appeared twice. Running each query once in CI is what catches it.
- 2026-09-20 · The ops console defaults to graphite dark · It is a palette, not a separate design, so the switcher still overrides it and every other palette renders.
- 2026-09-20 · Flags are read from admin settings, with environment variables on top · The point of a flag is to switch a behaviour during a session without a rebuild, so it has to be editable in the running app. An env var still wins, which is what the e2e suite relies on.
- 2026-09-20 · The search predicate stays index-only · An ILIKE on the reference or the model name forced a sequential scan and was redundant, because both fields are already in the haystack. Measured in a production build with 5,000 listings: 860 ms before, 180 ms after.
- 2026-09-20 · Screenshots are a tool, not a gate · `npm run screenshots` renders every key screen in four palettes, light and dark, plus mobile. It stays out of the default e2e run.
- 2026-09-20 · The preview server is pinned to port 3000 · The Supabase auth redirect URLs, `NEXT_PUBLIC_SITE_URL` and the Stripe webhook target all name it, so `.claude/launch.json` sets `autoPort: false` rather than letting the port float.
- 2026-09-20 · A tab key combines href and label · Two tabs can legitimately share an href, which React reports as a duplicate key and which can drop or duplicate a tab.
- 2026-09-20 · Twelve palettes, including a near-neutral and a monochrome · "No brand colour" is a legitimate answer, and it is hard to judge one until you have seen the layout without any. `slate` and `ink` make that comparison possible.
- 2026-09-20 · Shape, depth, density and contrast are switchable like colour · They change the character of a page as much as hue does, and each is a single multiplier or token override rather than a second stylesheet.
- 2026-09-20 · A palette swatch is computed, not inherited · A custom property resolves at the element that declares it, so a nested `data-palette` cannot re-derive the brand ramp. The switcher computes each dot from the same hue and chroma, and a unit test fails if those drift from tokens.css.
- 2026-09-20 · A serif or grotesk option changes only the display face · Headings in Source Serif over a sans body is the academic-dossier look of mockup S3, and reads very differently from the same page set entirely in Inter.
- 2026-09-20 · Logo proposals live in the app, not in a slide · A mark is judged in the header at 24 pixels beside real navigation, in the palette and typeface it will actually sit in. Eighteen lockups are selectable like any other design dimension.
- 2026-09-20 · Every mark is drawn on the same 24-unit grid with the same stroke · Mixed viewBoxes make marks look like different sizes beside each other, and a mark that falls apart at 20 pixels is no use as a favicon. A unit test enforces the grid.
- 2026-09-20 · The logo follows the attribute the switcher owns · It is a component rather than a CSS token, so a server-rendered header lagged one navigation behind `?logo=`. Subscribing to `data-logo` on the document element keeps one owner of the state and makes both a query parameter and a click in the panel take effect at once.
- 2026-09-20 · Marks share a height, not a width · The bench scene is a figure beside a rack and is genuinely wider than a flask; forcing it into the square grid distorted it. Every mark now declares its own viewBox width at a fixed height of 24 and is laid out by height.
- 2026-09-20 · Real photographs are opt-in and never committed · Generated placeholders remain the default so a fresh clone works offline and depends on nobody else's pictures. Fetched images live in local storage with a gitignored manifest recording source, licence and author.
- 2026-09-20 · Wikimedia Commons is the default image source, not a competitor's catalogue · It is openly licensed, so attribution is all that is needed, and it can be searched per equipment category, which puts a centrifuge photograph on a centrifuge listing. labfinder.ch remains available with `--source labfinder`, but those photographs are not ours to publish and that site is a directory rather than a catalogue: about twenty distinct product shots against ninety-five from Commons.
- 2026-09-20 · The e2e reseed keeps whichever images are in use · Otherwise running the tests silently reverted the catalogue to placeholders in the middle of a design review.
- 2026-10-04 · "Qualifizierte Geräte" is a page of its own, and until accreditation is modelled it lists verified listings that carry a warranty · The product owner defined qualified as: repaired, fitted with spare parts and qualified by a firm that refreshLab accredited for that work, with a warranty of 3 to 24 months that is either full or limited to named components. None of that has a field yet (execution plan §9, item 9), so `verified_at` plus `warranty_months > 0` stands in and the rule itself is stated in copy only.
- 2026-10-04 · "Ersatzteillager" lists the listings in condition `for_parts` · That is the product owner's definition: equipment declared defective and offered as a donor for boards, fans, knobs and handles. The condition already exists, so the store is a view of the open marketplace, not a new listing type.
- 2026-10-04 · The main navigation sits on a row of its own below the search field · Five entries do not fit beside the logo, the search field and the account controls at 1024 px: on one row the labels wrapped and the page scrolled sideways at tablet width. The second row holds them from 768 px, wraps onto a further line in a narrow window, and leaves room for more.
- 2026-10-04 · "Verbrauchsmaterialien" states its rule in copy and lists nothing yet · The product owner's rule: surplus, tangible, non-hazardous material from projects, over-orders and cleared laboratories (tips, filters, gloves, glassware); chemicals are excluded because nobody can vouch for what is in the container. A listing hangs on an equipment model, so nothing can be offered there yet. The page says so instead of faking stock, and stays out of the index and the sitemap until consumables can be listed.
- 2026-10-19 · Six warm paper themes, with sand as the default for now · The product owner found the dark theme too harsh and white too bright, then wanted more than one beige to choose from: cream, vanilla, linen, sand, greige and latte. Paper is a theme, not a palette, because it changes the surfaces and text rather than the brand hue, so every palette still works on top of it. Each variant is three paper values plus a card lightness, and ink deepens on the darker ones; primary goes one step deeper on all of them, which keeps links above AA. Light, dark and system stay one click away, and only "system" follows the operating system now.
- 2026-10-19 · The design cookie stores only choices that differ from the defaults, under a new name · The switcher used to write every dimension on every visit, which froze the defaults of that day: the new beige default would never have reached anyone who had opened the site before. The old cookie is ignored, so earlier panel choices are reset once.
- 2026-10-19 · "Geräte entdecken" opens with two highlight rows above the list · The product owner wanted the newest listings set apart: three newest qualified, then three newest of all. They show only on the plain view (nothing searched, filtered or re-sorted), and the list leaves them out on every page, so nothing appears twice and the pages stay stable. The facets and the heading still count them. Three per row, because the results column next to the filter rail has room for three cards at 1024 px.
